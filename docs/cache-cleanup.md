# Foundation 缓存与卸载残留

本指南不依赖已安装 Foundation 或用户级 Skill。自然请求“清理 Foundation 缓存”不保证任意新任务自动发现本文；找不到时请提供本指南链接，或只询问原安装位置。不要重新安装软件来清理缓存，不扫描整个磁盘。

## 只读发现

macOS 使用当前 OS 账户的真实主目录，不硬编码作者路径、不改 HOME。只检查以下明确约定：

- `Library/Caches/ai-product-foundation-kit-acquisition/` 中每个独占获取目录的 `acquisition.json`：下载归档/展开候选的来源版本、摘要和用途线索。它不是所有权或删除批准。
- 用户明确提供的原安装根的 `uninstall-result.json`：普通 JSON，保留卸载结果与 `residualInventory`（新版产生）。旧回执没有该字段时按 `residualPaths` 重新盘点，不补造旧证据。
- 同一安装根父目录 `.foundation-lifecycle-coordinator/` 的已有协调结果，仅按已知安装路径的对应关系检查。不是下载缓存；保留小回执。
- 原对话已经披露的独占升级暂存目录。未记录位置时询问，不按相似目录名推断。

平台 manager 会话、authority key、审计记录与缓存不同。密钥可能仍用于校验本地签名回执、协调恢复或其他安装；不能因为已卸载就删全部密钥，也不宣称一切审计都必须永久保留。用途/活动关系无法证明时保留并说明。

## 说明与确认

逐项展示绝对 real path、类型、文件数/实际字节、来源版本/操作、摘要与设备/inode/owner、用途、是否仍在使用、建议删或留及原因。符号链接不跟随。目录大小未知不能填 0；计数不要走入用户项目或链接。

区分下载缓存、升级暂存、审计记录和用户项目。机器索引里历史 `enabled` 不代表当前有效接入；新版正常卸载将机器索引停用并保留 `uninstallHistory`。旧索引不得手写或重签；以 installed current、项目 binding 和卸载回执交叉判断，冲突列为历史/待核实。

取得用户针对精确文件集合的确认后，使用宿主普通文件工具清理。不调用已删除 launcher、不打开 Foundation 确认页、不把 JSON 中的任意路径直接交给递归删除。确认后再次核对每级祖先、real path、类型、身份、摘要与活动消费者；漂移、共享、在用、未知或用户修改文件保留。逐文件删除，目录只在确认为空时移除；不清空父目录。

默认保留小型 uninstall-result.json、项目身份/facts/源码/备份、当前与回退版本、共享缓存、用途未明的密钥和审计。清理后重新盘点并报告删除项、残留与原因。清理失败不会改变之前已核实的安装/更新/卸载结果；重试清理不能重放生命周期操作。

## 本次升级成功后的暂存清理

采用已有 Codex 宿主后处理，不新增独立清理器或后台服务。开始更新前，将本次独占下载归档、入口副本和展开候选的精确路径、字节身份、成功触发条件与保留项一并披露并授权。不能借更新批准追溯删除历史升级目录。

新版当前管理器在 `manager inspect` 声明 `supportedLifecycleOptions.update` 包含 `cleanupAcquisition` 时，可在 update 请求附加该布尔意向。它不是执行许可：管理器从候选父目录的获取回执和实际文件构建只读 `hostCleanup` 清单，绑定在同一计划 hash 与确认会话；页面在确认按钮前展示清理路径、容量、条件和保留项。实际删除仍由持续观察同次操作的宿主普通文件工具执行，不由页面、安装引擎或后台服务执行。旧 manager 不具备该字段时须在对话先取得精确后处理授权，不能声称旧页面已获得新功能。

`hostCleanup.files` 给出绝对路径、bytes、mode、sha256、device、inode、uid；`directories` 只允许身份仍匹配且实际为空时移除。获取回执是输入线索，不是独立来源证明或所有权批准。`cleanup-result.json` 记录同次 planHash/operationId、实际版本与健康/事务/消费者退出证据、删除列表、保留原因和独立清理状态；小回执留在原获取目录。启动器本身来自共享 npm 缓存，不能按本次更新清理。

只有同次操作结束、已安装 current/版本/身份/健康均核实、所有输入消费者结束后，才允许清理上述本次输入。失败、中断、结果未知、仍在运行或共享输入均保留。先留下小型结果摘要（操作、版本、成功证据、清理/保留列表），不复制整包；然后按前述逐文件复核删除。即使文件消失也要核验并记录，不猜测上次清理成功。

这是宿主后处理合同；只有实际执行和复验才能记自动后处理通过。普通终端或已结束对话不会被本文自动唤醒。公开说明发现、真人确认清理和宿主接续尚需各自实测，本文不是 PASS。
